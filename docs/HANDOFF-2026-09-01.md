## 2. What is settled — do not re-litigate

**The phonon threshold "defect" does not exist.** Measured: the shipped `corr` converges
to π/4, taking the discrete 4Δ to Kaplan's πΔ exactly. For a **point-sample** phonon
state that rescale *is* the correct midpoint→line-integral conversion. Shipped-vs-split
converges to 1 (0.966 → 0.998 over an 8× refinement). An earlier "16% non-convergent"
claim came from comparing an **uncorrected** path the engine never takes.

**The area split must not be wired.** Its loss operator is `L = Σ w·vvᵀ` with `v = (s,1−s) ≥ 0`
— a Gram matrix, symmetric with non-negative off-diagonals. Loss enters as `−Ln`, so an
empty bin adjacent to an occupied one is driven **negative**. *The symmetry that makes
detailed balance exact is what destroys positivity.* `pair_split.py` / `omega_lattice.py`
remain valid as a quadrature comparison only; the kinetic entry points raise on a split.

**Collocation:** quasiparticles are cell averages, phonons are point samples. Both
correct. A point sample undercounts the gap-edge cell by exactly **1/√2 = 29.3% at every
resolution**. An error surviving refinement is in the *representation*, not the mesh —
distinguish that from merely under-resolved before calling anything non-convergent.

**The Debye assumption:** the `ω²` in the QP kernel is `α²F/b`, not kinematic. The QP
equation integrates over modes and carries a density of states; the phonon equation is
per mode and must not. **Never add a per-bin phonon DOS** — it double-counts.

## 4. How to not reintroduce this codebase's defect

Everything above is downstream of one recurring failure: **code whose stated behaviour is
bound to its real behaviour only by convention.** It hides because the arithmetic stays
self-consistent and only the *statement* is false, so nothing goes red. Instances found
and fixed in the last two days:

- `strategy='steady_state'` accepted `initial`, `drives`, `injection` and discarded them —
  bit-identical to 11 digits with injection at 2e-4 and 2e-1 — while the terms panel said
  the source was `on`.
- A field type (`"text"`) declared and **never dispatched**, so every string control
  silently discarded typing. `geometry.gds_path` had been inert since it was written.
- `boundary.per_edge` bound to a `"params"` box that accepts only a flat number map, so
  its nested value was rejected on every change (found 2026-09-01, after Wave 1 had
  tested the *engine* side of per-edge from Python and never the control).
- A benchmark validator binding its rebuilt frequency lattice to the run's by **bin
  count**, which passes while every frequency differs by half a bin.
- `benchmark` silently dropped on setup save/load.

**Working rules that came out of it:**

1. **A binding test must measure a number moving,** not that a call succeeds or a field
   posts. Both plot tests in `test_wave0_truthfulness.py` render *twice*, with and
   without the array, and require the output to change.
2. **Drive the setup.** Undriven, every solver and every phonon sector returns
   bit-identical results — the thermal state is the fixed point — so any binding test
   built on one is vacuous.
3. **Grep for a second implementation before believing a fix landed.** One adjudicated fix
   this project landed on one of two copies and was inert on the path that mattered.
4. **Compare against the path the engine actually takes.** Two wrong conclusions this
   session came from measuring something adjacent — an uncorrected code path, and a
   window that measured bin edges rather than physics.
5. **Verify memory before repeating it.** A note saying the branch was unpushed had gone
   stale and was repeated as a top-priority risk. "N commits ahead of `origin/main`" is
   **not** "unpushed" — check `git log origin/<branch>..HEAD`.
